# audiblez

Converts an `.epub` or text-based `.pdf` into an `.m4b` audiobook with chapter markers, cover (EPUB) and
title/author metadata. Speech is generated by an OpenAI-compatible TTS server (by default the `phonon` model on the
user's Ollama Mac, roughly 50x faster than real time), or by Kokoro running locally.

## When to Use

- The user asks for an audiobook, or to "read", "narrate" or "convert to audio" a book, ebook, PDF, sermon or story.
- The user wants a story narrated with different voices for its characters.
- Not for scanned/image-only PDFs: there is no OCR. If `audiblez` reports 0 paragraphs, say the PDF has no text layer.

## Quick Reference

| Task | Command |
|---|---|
| Install / upgrade | `bash ${HERMES_SKILL_DIR}/scripts/install.sh "<tts_base_url>" "<tts_model>" "<voice>" "<llm_model>"` |
| List voices | `audiblez --list-voices` |
| Audiobook | `audiblez BOOK -o OUT` |
| Quick sample (first chapter only) | `audiblez BOOK -o OUT --max-chapters 1` |
| Specific voice / speed | `audiblez BOOK -o OUT -v "Hugh" -s 1.1` |
| Voice that fits the author (e.g. British male for Spurgeon) | `audiblez BOOK -o OUT --auto-narrator` |
| Character voices: detect cast | `audiblez BOOK -o OUT --characters` (writes `OUT/<stem>.cast.toml`, then stops) |
| Character voices: synthesize | run the same `--characters` command again |
| Character voices in one go | `audiblez BOOK -o OUT --characters --no-review` |
| Faster, without checking each clip | add `--no-verify` |
| Use a cloud LLM for this run | add `--llm-model kimi-k3:cloud` |
| Audition every voice | `audiblez --audition-voices -o OUT` |

`BOOK` is the path to the `.epub` or `.pdf`; `OUT` is a folder for this book, e.g. `{audiblez.output_dir}/<book name>`.
The result is `OUT/<stem>.m4b`, where `<stem>` is the book's file name without the extension.

## Procedure

1. **Install if needed.** If `audiblez --help` fails, or if `audiblez --help` doesn't mention `--characters`, run the
   install script with the configured values:
   `bash ${HERMES_SKILL_DIR}/scripts/install.sh "{audiblez.tts_base_url}" "{audiblez.tts_model}" "{audiblez.voice}" "{audiblez.llm_model}"`.
   It writes `~/.config/audiblez/config.toml` only if none exists. Edit that file to change providers later.
2. **Get the book onto disk** (download the user's link or save their attachment) in a folder of its own.
3. **Choose the mode.**
   - Default: plain narration in the configured voice.
   - Fiction with dialogue, or the user asks for character voices: use `--characters`.
   - Sermons, essays, classics by a known author: suggest `--auto-narrator`. It only switches voice when it is
     confident and a voice with the matching gender and accent is tagged in the config.
   - Don't use `--characters` on non-fiction: quotations there are mostly citations, not dialogue.
4. **Run it in the background**: a full book takes from minutes (phonon) to hours (Kokoro on CPU). Use a log:
   `mkdir -p OUT && nohup audiblez BOOK -o OUT [options] > OUT/audiblez.log 2>&1 &`
   Report progress from `tail -n 3 OUT/audiblez.log` (it prints `Progress: NN%` and an ETA) when the user asks.
5. **Character voices take two runs.** The first `--characters` run asks the LLM who speaks each quote, then writes
   the cast sheet and stops. Show the user the cast table from the log (character, gender, lines, voice). Ask if
   they want changes, edit the `voice = "..."` lines in `OUT/<stem>.cast.toml`, then run the same command again.
   If the user asked for it all in one go, add `--no-review`.
6. **Deliver** `OUT/<stem>.m4b`. Once the m4b exists, the `OUT/<stem>_chapter_*.wav` files can be deleted to free
   space. Keep them while a run may be resumed: re-running skips chapters whose wav already exists.

## Pitfalls

- **TTS server busy or unreachable**: the Ollama Mac also runs other models. Requests are retried, but a long
  queue can time out. Check with `audiblez --list-voices`. If `.local` doesn't resolve on this machine, use the
  Mac's IP address in `~/.config/audiblez/config.toml`.
- **Clip verification**: every clip is checked with a small speech recognizer (installed by the install script),
  and clips where the TTS model dropped or invented words are regenerated. Lines like `TTS glitch (...)
  regenerating` in the log are this working, not an error. It roughly doubles the run time; `--no-verify` skips it.
- **Speed**: phonon only speaks at 1.0. Other speeds are applied when the m4b is made, which works fine.
- **Wrong chapters picked**: the log prints a table of all sections with ✅ on the selected ones. PDFs use their
  bookmarks, or larger-font headings when there are none. Front matter (cover, contents) is skipped. Long
  sections are split into "(part N)" pieces between paragraphs.
- **Character voices need a tagged voice list.** Ollama doesn't report gender or accent. Without tags, all characters
  are read by the narrator. `audiblez --audition-voices` prints a snippet with pitch-based gender guesses to add to
  the config under `[providers.ollama.voices]`. Accents must be filled in by someone listening.
- **Re-casting**: editing the cast sheet automatically re-synthesizes the affected book (the wav names include a
  hash of the cast). To re-detect the characters, delete `OUT/<stem>.cast.toml` and `OUT/<stem>.speakers.json`.
- **Cloud LLM models** (`*:cloud`) use the user's Ollama cloud quota. Use them only when the user asks, or after
  asking first.

## Verification

- `ffprobe -v error -show_entries format=duration:chapter_tags=title -of compact OUT/<stem>.m4b` shows a duration
  and one chapter line per section.
- The log ends with `... .m4b created. Enjoy your audiobook.`
